2026-07-06 验证结果与关键修正

关键发现 1：area_values 文件中的 R 值计算有误
- 在 main.py 的 process_metrics_from_manager() 中，原本使用 attack_step/initial_nodes 作为 x 轴计算 R 值
- 当攻击序列攻击已不存在的节点时（如 adaptive 攻击），attack_step 会大于实际移除节点数，导致 x 轴被拉长、R 值被严重低估
- 例如 Colt/adaptive_bridge batch=3 中，BiT-HyRL 的 comprehensive R=0.4638，而 area_values 错误显示为 0.1612
- 已修复 main.py：R 值计算统一使用 curve_data 中已有的实际移除节点比例 x_curve
- 修复后 BA-50/random 测试确认 comprehensive R 与 area_values 完全一致

关键发现 2：comprehensive_metrics.csv 中的 R 值才是正确的 GCC Area
- 它使用 manager.py 中 curve_data 的实际移除比例 x_val = (nodes_num - current_nodes)/nodes_num
- 后续所有结论都应基于 comprehensive_metrics.csv 中的 R 值

三组验证实验结果（基于正确的 comprehensive R）：

1) Colt/random batch=3（多 seed 评分后）
   a) PPO 微调拓扑 + PPO 控制器（results/Colt/random/10）：
      - BiT-HyRL:        0.4153
      - BiT-HyRL-base:   0.4650  ← 最好
      - ROMEN+RL:        0.4479
   b) PPO 微调拓扑 + GNN 控制器（results/Colt/random/14）：
      - BiT-HyRL:        0.4562  ← 最好
      - BiT-HyRL-base:   0.4506
      - ROMEN+RL:        0.4150
   - 结论：PPO 选择的控制器在 random 攻击下不如 GNN 控制器稳健；BiT-HyRL-base（原双峰+GNN）整体非常强劲

2) GtsCe/wgcc batch=3（results/GtsCe/wgcc/8）
   - BiT-HyRL-base:   0.4680  ← 最好
   - BiT-HyRL:        0.4520
   - QDLM:            0.4278
   - FRED-ABL:        0.3995
   - ROMEN+RL:        0.3737
   - 结论：BiT-HyRL 家族在 wgcc 混合攻击下保持显著优势；PPO 微调在此场景略逊于原双峰

3) Colt/adaptive_bridge batch=3（results/Colt/adaptive_bridge/1）
   - BiT-HyRL:        0.4638  ← 最好
   - BiT-HyRL-base:   0.4561
   - GA+RL:           0.4496
   - UNITY+RL:        0.4447
   - ROMEN+RL:        0.4206
   - 结论：在 adaptive_bridge 攻击下，PPO 微调对 BiT-HyRL 有正向帮助，BiT-HyRL 整体领先

综合结论：
- BiT-HyRL-base（双峰拓扑 + GNN 控制器，无 PPO 微调）在 Colt/random 和 GtsCe/wgcc 上表现最好或接近最好，且方差较小
- Unified-PPO 微调不是 universally 有益的：在 adaptive_bridge 有帮助，在 random/wgcc 可能略微负面或增加方差
- PPO 控制器选择不如 GNN 控制器稳健
- 主要问题已从 "BiT-HyRL 落后于 ROMEN+RL" 转变为 "如何让 PPO 微调真正提升已很强的 BiT-HyRL-base"
